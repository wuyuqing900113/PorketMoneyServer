# 渗透测试机制与首轮计划（M6）

| 项 | 值 |
|---|---|
| 里程碑 | M6（测试加固与安全） |
| 依据 | `M6-detailed-design.md` §8.3（D53） |
| 日期 | 2026-08-28 |

---

## 1. 机制（D53）

- **频率**：每季度一次 + 首轮 GA（正式发布）前一次。
- **触发**：季度例行；重大变更（新增资金链路、接入第三方 AI/ASR/TTS provider、权限模型调整）时临时加测。

## 2. 范围（Scope）

| 域 | 渗透对象 |
|---|---|
| 认证/授权 | JWT 双令牌签发/校验/轮转/重用吊销；`FamilyAccessChecker` 数据级越权；`@PreAuthorize` 方法级权限 |
| 资金写接口 | 幂等键（`IdempotencyKeys`）预占与并发重放；跨家庭资金篡改 |
| 越权（IDOR） | 篡改 `familyId` / `userId` / 业务 `id` 路径参数遍历他人资源 |
| 注入 | SQL 注入（MyBatis 参数化核验）、日志注入、恶意输入 |
| AI 指令越权 | AI 意图解析二次确认绕过（孩子操作需家长二次确认） |
| 敏感数据暴露 | 出参是否泄露密码哈希/密钥/明文手机号/身份证 |

## 3. 方法

- **人工**：针对上述范围的手工测试用例（复用 `PermissionMatrixPgIntegrationTest` / `M2PermissionMatrixPgIntegrationTest` 覆盖矩阵，M6 已增补 `IdorSecurityTest` 跨家庭 ID 遍历）。
- **扫描器**：OWASP ZAP（或同类）对 API 做自动化被动/主动扫描；依赖已知漏洞扫描由云效代码检测组件承载（D48）。

## 4. 报告分级与处置闭环

- **分级**：高危 / 中危 / 低危。
- **处置**：高危必修（修复 + 回归）；中低危有处置计划（记录至 M7 或后续）。
- **复测**：修复后对受影响范围复测确认闭环。

## 5. 首轮计划（GA 前）

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1. 范围界定 | 上述 §2 全量范围 | 本文件 |
| 2. 工具/手法 | ZAP 自动化 + 人工用例（含 M6 安全测试套件回归） | 扫描配置 + 用例清单 |
| 3. 执行 | GA 前环境（与生产同构，不含真实数据） | 原始报告（存档，不入库） |
| 4. 分级 | 高危/中危/低危定级 | 处置清单 |
| 5. 处置 | 高危必修 + 复测 | 回归记录 |

## 6. 结果存档规则

- **报告不入仓库**：渗透测试原始报告含攻击细节与敏感信息，**仅存结论与处置项**（避免泄露细节）；完整报告存内部安全库/工单系统。
- **入库内容**：本计划 + 处置结论（更新至 `owasp-self-check-report.md` 的「发现与处置」章节）。
